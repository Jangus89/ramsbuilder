SafeFlow PDF Export Review

Generated as a review artifact for the PDF export hardening work.

What Changed

  • The PDF/print export no longer builds a document by interpolating RAMS data into an HTML string.
  • The export now opens a print window and constructs the document using DOM nodes and textContent.
  • Risk labels are normalised to known CSS classes before being applied.
  • Generated text, user-entered text, and AI-returned content are treated as text, not executable markup.

Why It Matters

The previous implementation used document.write with generated RAMS fields embedded directly in HTML. If a generated value contained HTML-like content, it could alter the exported document structure. The new path avoids that by assigning all RAMS content through text nodes.

Verification

  • npm run build passes.
  • OpenAI calls now use shared error handling through lib/openaiClient.js.
  • The job description field is now a larger textarea labelled "Tell us about the job".
  • Supabase and OpenAI environment variables are present locally.
